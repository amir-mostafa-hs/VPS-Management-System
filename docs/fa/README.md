# راهنمای جامع فارسی زیرساخت سرور مجازی (`vps-infrastructure`)

این مستند یک راهنمای گام‌به‌گام، ساده و کاربردی برای راه‌اندازی و مدیریت یک سرور مجازی لینوکس (VPS) اختصاصی با استفاده از ابزار **کولیفای (Coolify)**، سیستم بیلد برون‌سپاری‌شده در **گیت‌هاب (GitHub Actions & GHCR)** و پشتیبان‌گیری خودکار رمزنگاری‌شده روی **گوگل درایو (Google Drive)** است.

## ۱. معماری سیستم به زبان ساده

تصور کنید سرور شما مانند یک فروشگاه جمع‌وجور است. در حالت‌های سنتی، برنامه‌نویسان سعی می‌کنند کارخانه، بسته‌بندی کالا، انبار و صندوق‌داری را همه داخل همان سرور کوچک قرار دهند. نتیجه این می‌شود که در هنگام کامپایل یا بیلد نرم‌افزار، مصرف رم و پردازنده به ۱۰۰٪ می‌رسد و سایت‌ها از کار می‌افتند.

در معماری این مخزن:
1. **ساخت کانتینرها (Build):** ۱۰۰٪ به رانرهای قدرتمند و رایگان گیت‌هاب واگذار شده است. ایمیج‌های ساخته‌شده در فضای ذخیره‌سازی خصوصی گیت‌هاب (GHCR) ذخیره می‌شوند.
2. **میزبانی و اجرا (Host):** سرور VPS شما تنها نسخه‌های آماده را دانلود کرده و بدون فشار پردازشی اجرا می‌کند.
3. **مدیریت هاست (Coolify PaaS):** رابط گرافیکی تحت وب کولیفای کار مسیریابی دامنه‌ها، صدور گواهی امنیتی SSL و متغیرهای محیطی را به صورت خودکار انجام می‌دهد.
4. **پشتیبان‌گیری امن (Encrypted Backups):** دیتابیس‌ها و تنظیمات شبانه داخل خود سرور با قوی‌ترین استاندارد رمزنگاری (AES-256) قفل می‌شوند و سپس نسخه قفل‌شده به گوگل درایو آپلود می‌شود.

```text
 [شما: گیت پوش] ──► [گیت‌هاب اکشن: بیلد پرسرعت] ──► [رجیستری GHCR: ایمیج نهایی]
                                                             │
  [گیت‌هاب اکشن] ──► وب‌هوک دیپلوی ──► [کولیفای روی سرور] ◄──┘ (دانلود و اجرای سریع)
                                              │
                                  بک‌آپ شبانه و رمزنگاری
                                              ▼
                                 [فضای ابری Google Drive]
```

## ۲. چرا این تصمیمات معماری گرفته شدند؟

| تصمیم | علت و دلیل فنی |
|---|---|
| **عدم بیلد روی سرور VPS** | سرورهای کوچک (۲ تا ۴ گیگابایت رم) در زمان بیلد سنگین دچار خطای کمبود حافظه (OOM) می‌شوند و پایگاه‌های داده کرش می‌کنند. گیت‌هاب رانرهایی با ۱۶ گیگابایت رم رایگان در اختیار می‌گذارد. |
| **استفاده از پلتفرم Coolify** | کولیفای جایگزین سلف‌هاستد هروکو (Heroku) و ورسل (Vercel) است. این پلتفرم تمام تنظیمات پروکسی معکوس (Traefik)، صدور گواهی رایگان Let's Encrypt و مدیریت ولوم‌ها را خودکار می‌کند. |
| **فایروال مسدودسازی پیش‌فرض (Default-Deny)** | تمام درگاه‌های شبکه بسته هستند مگر پورت ۲۲ (مدیریت)، ۸۰ و ۴۴۳ (وب)، و ۸۰۰۰ (پنل کولیفای). هر پورت دیگری باید صراحتاً در فایل `config/allowed_ports.conf` تعریف شود. |
| **رمزنگاری سمت کلاینت با `rclone crypt`** | داده‌های حساس دیتابیس پیش از ارسال به فضای ابری گوگل، روی خود سرور رمزگذاری متقارن می‌شوند. اگر حساب گوگل یا دسترسی ابری هک شود، سارق فقط فایل‌های بی‌معنی و رمزگذاری شده را می‌بیند. |

## ۳. پیش‌نیازها قبل از شروع

1. **سرور مجازی (VPS):** با مجازی‌سازی KVM (پشتیبانی از کرنل مستقل)، سیستم‌عامل پیشنهادی Ubuntu 24.04 LTS یا Debian 12، حداقل ۱ هسته پردازنده و ۲ گیگابایت حافظه رم.
2. **یک دامنه یا ساب‌دامنه اینترنتی:** در پنل کلودفلر یا ثبت‌کننده دامنه خود رکوردهای زیر را به آی‌پی سرور متصل کنید:
   - `coolify.yourdomain.com` (نوع: `A` به سمت IP سرور)
   - `*.yourdomain.com` (نوع: `A` به سمت IP سرور - رکورد وایلدکارت جهت اتصال آسان برنامه‌ها)
   *(نکته: در کلودفلر ابتدا ابر خاکستری یا DNS-Only را انتخاب کنید تا صدور اولیه SSL با موفقیت انجام شود).*
3. **کلید احراز هویت SSH:** در کامپیوتر شخصی خود با دستور زیر کلید تولید کنید:
   ```bash
   ssh-keygen -t ed25519 -C "admin@vps"
   ```

## ۴. مراحل گام‌به‌گام راه‌اندازی سرور خام

### گام ۱: اتصال اولیه و ساخت کاربر مدیریت
با کاربر root وارد سرور شوید:
```bash
ssh root@<IP_SERVER>
```
سپس کاربر ادمین بدون دسترسی مستقیم روت بسازید:
```bash
# ساخت کاربر deployer
adduser --gecos "" deployer
usermod -aG sudo deployer
echo "deployer ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/deployer
chmod 0440 /etc/sudoers.d/deployer

# انتقال کلید SSH به کاربر جدید
mkdir -p /home/deployer/.ssh && chmod 700 /home/deployer/.ssh
cp /root/.ssh/authorized_keys /home/deployer/.ssh/
chmod 600 /home/deployer/.ssh/authorized_keys
chown -R deployer:deployer /home/deployer/.ssh
```

> [!CAUTION]
> پنجره اتصال root فعلی را نبندید! یک پنجره ترمینال جدید در کامپیوتر خود باز کرده و اتصال کاربر جدید را تست کنید:
> ```bash
> ssh deployer@<IP_SERVER>
> sudo whoami # باید خروجی root باشد
> ```

### گام ۲: تنظیم ساعت و کلون کردن ریپازیتوری
```bash
# تنظیم ساعت به UTC (ضروری برای همزمانی لاگ‌ها و بک‌آپ‌ها)
sudo timedatectl set-timezone UTC

# نصب پکیج‌های گیت و میک
sudo apt-get update && sudo apt-get install -y git make

# کلون کردن مخزن
git clone https://github.com/<your-org>/vps-infrastructure.git
cd vps-infrastructure
```

### گام ۳: اجرای تست‌های پیش‌نیاز و آماده‌سازی سیستم
```bash
# بررسی سخت‌افزار و سیستم‌عامل
make preflight

# نصب ابزارهای پایه لینوکس (curl, ufw, fail2ban, rclone, jq)
make bootstrap
```

### گام ۴: اعمال سخت‌سازی امنیتی و فایروال
اگر پورت اختصاصی اضافه‌ای نیاز دارید، آن را در انتهای فایل `config/allowed_ports.conf` بنویسید (مثلاً `8080/tcp`). سپس دستور زیر را اجرا کنید:
```bash
# اجرای خودکار فایروال و تنظیمات امنیتی SSH
make harden
```
این دستور ورود با پسورد را قطع می‌کند، حملات Brute Force را از طریق Fail2ban مسدود می‌سازد و فقط پورت‌های مجاز را باز نگه می‌دارد.

### گام ۵: نصب داکر و کولیفای (Docker & Coolify)
```bash
# نصب داکر رسمی با محدودسازی حجم لاگ‌ها
make install-docker

# نصب کولیفای نسخه ۴
make install-coolify
```

> [!IMPORTANT]
> **خیلی مهم - بلافاصله کلید APP_KEY را ذخیره کنید:**  
> کولیفای تمام پسوردها و سکرت‌های شما را با یک کلید مستر به نام `APP_KEY` رمز می‌کند. این کلید را همین حالا بخوانید و در پسورد منیجر آفلاین خود (مانند Bitwarden یا 1Password) ذخیره کنید:
> ```bash
> sudo grep '^APP_KEY=' /data/coolify/source/.env
> ```
> *اگر این کلید گم شود، هیچ دیتابیس یا سکرتی در صورت خرابی سرور قابل بازیابی نخواهد بود!*

### گام ۶: ورود به داشبورد کولیفای
مرورگر را باز کرده و به آدرس زیر بروید:
```text
http://<IP_SERVER>:8000
```
- حساب کاربری اولین مدیر را با ایمیل و رمزعبور قوی ایجاد کنید.
- در منوی تنظیمات (Settings)، دامنه سرور را روی `https://coolify.yourdomain.com` تنظیم کنید تا SSL خودکار فعال شود.

## ۵. تنظیم بک‌آپ رمزنگاری‌شده روزانه روی Google Drive

### مرحله ۱: اتصال به گوگل درایو
روی سرور دستور `rclone config` را بزنید:
- یک ریموت جدید به نام `gdrive` از نوع `drive` بسازید.
- چون سرور مرورگر گرافیکی ندارد، در پاسخ به باز کردن خودکار مرورگر گزینه `n` را بزنید.
- در کامپیوتر شخصی خود دستور داده‌شده (`rclone authorize "drive" ...`) را بزنید، در مرورگر لاگین کرده و توکن دریافتی را در سرور پیست کنید.

### مرحله ۲: ایجاد لایه رمزنگاری (`gdrive-crypt`)
دوباره در `rclone config` یک ریموت از نوع `crypt` به نام `gdrive-crypt` بسازید:
- آدرس ریموت پایه را `gdrive:vps-backups` قرار دهید.
- رمزعبور و Salt تصادفی و قوی ایجاد کرده و آن را هم در پسورد منیجر خود یادداشت کنید.

### مرحله ۳: فعال‌سازی سیستم بک‌آپ خودکار
```bash
# ایجاد فایل تنظیمات
cp config/backup.example.env config/backup.env
chmod 600 config/backup.env

# نصب و فعال‌سازی تایمر زمان‌بندی systemd
make backup-setup

# تست اجرای اولین بک‌آپ بلافاصله
make backup-now

# بررسی لیست فایل‌های ذخیره شده در گوگل درایو
make backup-verify
```
از این پس سرور هر شب در ساعت ۰۳:۰۰ به وقت جهانی (UTC) به صورت خودکار پشتیبان‌گیری کرده و آرشیوهای قدیمی‌تر از ۷ روز محلی و ۳۰ روز ابری را پاک‌سازی می‌کند.

## ۶. نحوه استقرار و دیپلوی پروژه‌های نرم‌افزاری (CI/CD)

1. در کولیفای به بخش **Keys & Servers** > **Registries** بروید و اکانت گیت‌هاب خود را برای دسترسی به `ghcr.io` اضافه کنید (با یک Personal Access Token دارای دسترسی `read:packages`).
2. یک منبع جدید از نوع **Docker Image** در کولیفای بسازید و آدرس آن را `ghcr.io/<نام-کاربری>/<نام-پروژه>:latest` بگذارید.
3. در تنظیمات برنامه در کولیفای، آدرس **Deploy Webhook** را کپی کنید.
4. در ریپازیتوری پروژه خود در گیت‌هاب، فایل اکشن `.github/workflows/reusable-docker-build.yml` موجود در این مخزن را به پروژه منتقل کنید و آدرس وب‌هوک را در سکرت `COOLIFY_DEPLOY_WEBHOOK` قرار دهید.
5. از این پس با هر `git push` به شاخه `main`، گیت‌هاب کانتینر را می‌سازد و به کولیفای پیام دیپلوی می‌دهد. سرور شما در عرض چند ثانیه برنامه را بدون هیچ فشاری آپدیت می‌کند!

## ۷. جدول دستورات روزمره Make

تمام ابزارها و کارهای سرور از طریق دستورات ساده Make مدیریت می‌شوند:

| دستور | توضیح عملکرد |
|---|---|
| `make help` | مشاهده لیست و راهنمای تمام دستورات موجود |
| `make health` | بررسی فوری سلامت سرور (رم، پردازنده، دیسک و کانتینرها) |
| `make check` | اعتبارسنجی سینتکس تمام اسکریپت‌ها و اسکن عدم وجود سکرت یا پسورد |
| `make test` | اجرای بیش از ۲۰۰ تست آفلاین کیفیت سنجی TDD |
| `make preflight` | عیب‌یابی اولیه و تست سازگاری سخت‌افزار سرور |
| `make bootstrap` | نصب و به‌روزرسانی پکیج‌های اصلی لینوکس |
| `make harden` | بازتنظیم فایروال UFW و سخت‌سازی SSH |
| `make install-docker` | نصب موتور رسمی داکر |
| `make install-coolify` | نصب و به‌روزرسانی کولیفای |
| `make backup-now` | ایجاد بک‌آپ دستی فوری و آپلود به گوگل درایو |
| `make backup-verify` | مشاهده ایمن فایل‌های بک‌آپ موجود در گوگل درایو |
| `make backup-restore` | ویزارد بازیابی اطلاعات در صورت نیاز به ریکاوری |
| `make clean` | پاک کردن فایل‌های موقت و کش‌های تستی |

> [!TIP]
> برای اجرای آزمایشی هر دستوری بدون اینکه تغییری در سرور ایجاد کند، می‌توانید فلگ `ARGS="--dry-run"` را ارسال کنید:
> ```bash
> make harden ARGS="--dry-run"
> ```

## ۸. عیب‌یابی سریع و راه‌حل مشکلات رایج

### ۱. مشکل: دسترسی SSH قفل شده و متصل نمی‌شود
- به پنل هاستینگ خود بروید و کنسول اضطراری وب (Web Console / VNC) را باز کنید.
- وضعیت فایروال را بررسی کنید: `sudo ufw status verbose`. در صورت نیاز پورت ۲۲ را باز کنید: `sudo ufw allow 22/tcp`.
- آی‌پی خود را در صورت بن شدن توسط Fail2ban آزاد کنید: `sudo fail2ban-client set sshd unbanip <YOUR_IP>`.

### ۲. مشکل: دیسک سرور ۱۰۰٪ پر شده است
- کش‌های بیلد داکر و کانتینرهای متوقف‌شده را پاک کنید: `docker system prune -af`.
- لاگ‌های سنگین سیستم را تا ۲۰۰ مگابایت پاک‌سازی کنید: `sudo journalctl --vacuum-size=200M`.

### ۳. مشکل: پنل کولیفای باز نمی‌شود
- وضعیت کانتینرها را بررسی کنید: `docker ps -a`.
- سرویس کولیفای را مجدداً راه‌اندازی کنید:
  ```bash
  cd /data/coolify/source && docker compose down && docker compose up -d
  ```
